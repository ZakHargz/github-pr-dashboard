# AGENTS.md — GitHub PR Dashboard

Context file for AI agents working in this repository. Read this before making changes.

---

## What this project is

A client-side GitHub PR dashboard. Users paste a Personal Access Token and a list of `owner/repo` pairs; the app calls the GitHub REST API directly from the browser and renders a two-panel layout: a collapsible repo/PR sidebar on the left and a PR detail panel on the right.

There is no backend. No database. No authentication server. The token is stored in `localStorage` and sent only to `api.github.com`.

  └── Dashboard
        ├── usePRData   prs, listLoading, listErrors, lastRefreshed,
        │               ciStatuses, reviewSummaries, autoRefresh

State is never duplicated between hooks. Each hook owns its slice.

## Key conventions

### Base UI, not Radix
`components/ui/` was generated by shadcn but the primitives are from `@base-ui/react`, not `@radix-ui`. The APIs differ. **Do not assume Radix API compatibility.** When working with `ScrollArea`, `Tooltip`, etc., check the actual component source in `components/ui/`.

### ScrollArea requirements
`ScrollAreaPrimitive.Root` requires `overflow-hidden` on the root element and `min-h-0` on any flex parent to properly constrain the scrollable viewport. Both are set — don't remove them.

### No icon library
All icons are inline SVGs in `components/icons/index.tsx`. Add new icons there as named components. Do not install an icon package.

### lib/github.ts is a pure fetch layer
No React imports. No hooks. No `useState`. Keep it that way — it must be importable from any context.

### Markdown rendering
`MarkdownBody.tsx` uses `rehype-raw` to allow GitHub's HTML (e.g. `<details>`/`<summary>` changelog blocks) to render correctly. Always include both `remarkPlugins={[remarkGfm]}` and `rehypePlugins={[rehypeRaw]}`.

### Timestamp components own their own ticks
`PRListHeader` has a 10-second `setInterval` for its "Updated X ago" display. `PRList` has a 30-second one for PR row relative times. Components that show relative times should own their own interval rather than relying on parent re-renders.

### Dark mode
Theme is controlled by the `dark` class on `<html>`. A blocking inline `<script>` in `layout.tsx` applies the class before React hydrates to prevent FOUC. `use-theme` subscribes via `MutationObserver` + `useSyncExternalStore`. `suppressHydrationWarning` is set on `<html>` intentionally.

### Fonts are disabled for Docker
`app/layout.tsx` has `next/font` imports commented out and replaced with empty variable stubs. This prevents build failures in offline/Docker environments. Re-enable them for non-Docker deployments if needed.

## Docker workflow

The Dockerfile is **runtime-only** — it copies pre-built artifacts from `.next/standalone`. You **must** run `npm run build` locally before `docker build`, otherwise the image contains stale compiled output.

```bash
# Always in this order:
npm run build
docker build -t github-pr-dashboard .
docker run -d -p 3000:3000 --name <name> github-pr-dashboard
```

The running container name has been `reverent_mcnulty`. To redeploy:
```bash
docker stop reverent_mcnulty && docker rm reverent_mcnulty
docker build -t github-pr-dashboard .
docker run -d -p 3000:3000 --name reverent_mcnulty github-pr-dashboard
```

There is no `.env` file — the GitHub token is entered in-browser and stored in `localStorage`. The container needs outbound access to `api.github.com` only.

## GitHub API usage

All calls go through `githubFetch()` in `lib/github.ts`:
- `Authorization: Bearer <token>`
- `Accept: application/vnd.github+json`
- `X-GitHub-Api-Version: 2022-11-28`

SAML SSO errors (HTTP 403 with "SAML enforcement" in the body) are thrown as `GitHubSAMLError` and surfaced as `RepoErrorBanner` in the sidebar.

The PR list uses `Promise.allSettled` so a single failing repo doesn't block the others. CI status and review summaries are fetched in the background after the PR list resolves (fire-and-forget, streamed into state as they arrive).
